置顶任务 · AI 剧目生成置顶

目标：在现有自有设备上高效产出多部 AI 剧目，突破"一台设备只能出一部剧"的产能瓶颈。 产出工具包已在本机实跑验证，四项核心结论均来自可复现的模拟与体检。

产能规划 + 评审一致性

一台设备能不能同时出多部剧？——能，但上限由显存钉死

用户原始需求："我们需要的是能基于我们设备的前提下高效制作 AI 剧目的程序……一台设备只能产出一部剧， 我们的想法是争取一台设备同时能产出多部剧目，提高效率"

核心结论：这个领域没有官方技术评测

沿用任务 1 的划线标准（注册制 + 官方 qrels/test set + 官方 scorer + proceedings）， AI 视频生成领域不存在 TREC / IWSLT 那种官方技术评测：

· 学术侧 VBench / EvalCrafter / FETV / T2VSafetyBench 均为研究团队发布的基准，无主办机制；
· 工业侧 Artificial Analysis Video Arena 为商业榜单，测试集不公开、不可复现；
· 国内赛事（鲸锐、河马杯、腾讯 i 短剧、北京 AIGC、上海提示未来）全部是作品评选型，评委主观打分，无技术指标。

根本原因：视频的"正确输出"无法枚举，Cranfield 范式在此失效；单部成片需数十机时， 参赛样本量支撑不起统计显著性检验；且买方是内容平台而非系统工程师，需求的是能播的片子。

应对：不硬套任务 1 的思路，改为把主观评审过程结构化（固定维度/权重/量表）， 并把评委一致性做成可计算的客观指标（Kendall's W）。

前世今生：从 Cranfield 到 LLM 判定

Cranfield（1950s–1966）：Cyril Cleverdon 建立 1,398 篇航空摘要 + 225 条查询的穷尽判定测试集，确立"固定文档集 + 固定查询集 + 固定标准答案"的受控比较范式。

TREC（1992 起）：DARPA TIPSTER 项目委托 NIST 构建 2 GB 测试集，1992 年首届 25 个团队参与，把系统从检索 2 MB 推进到 2 GB。规模扩大后穷尽判定失效，TREC 发明 pooling——只判各系统 Top-k 汇总去重后的文档。1992–1999 八届累计约 189 万篇文档、450 个主题。

全球扩散：CLEF（2000，欧洲跨语言）、NTCIR（1999，日本 NII，东亚多语言）、FIRE（2008，南亚）、TAC（2008，文本分析）、BioASQ（2012）、COLIEE（2014）、MS MARCO（2016，微软官方竞赛并成为 TREC DL 指定语料）。国内有 CCKS、NLPCC、CCIR、SMP、CCF BDCI、天池等。

最新范式转移（2024–）：TREC 2024/2025 RAG 首次大规模用 LLM 生成标准答案。UMBRELA 自动判定与全人工判定的系统排序 Kendall's τ 约 0.890，NIST 研究结论为"可替代全人工用于 run 级比较"。

技术路线：四代演进

第一代 布尔 / 向量空间 / TF-IDF —— 关注查全查准与索引效率。

第二代 概率模型 / BM25 / 语言模型 / 查询扩展 / 学习排序 —— MAP、nDCG 为主。

第三代 稠密检索（DPR、ANCE）、迟交互（ColBERT）、学习稀疏（SPLADE）、混合检索 —— 跨领域泛化成为焦点（受 BEIR 结论驱动）。

第四代 LLM 重排、生成式检索、RAG —— 评测对象从"排序列表"扩展到"带引用的生成答案"，催生 nugget 覆盖度、支持度等新指标。

五个关键决策

  • 检索单元定 构件 / 图元级，一旦定下不可改
  • 用 pooling 把标注成本压到十分之一以下
  • 一致性主判据用 二次加权 κ ≥ 0.6
  • paired bootstrap 显著性为硬要求
  • 把坑固化成脚本自动检查，而非写进文档

七步流程

  • ① 定检索单元 → ② 设计 topics（30–60）
  • ③ 多系统检索 → ④ pooling 汇总
  • ⑤ 双人标注 + 一致性检验
  • ⑥ qrels 体检 → ⑦ 评测 + 显著性
方法学溯源：为什么这三件套不能省

Cranfield 范式提供了受控比较的基本结构；TREC 的 pooling 解决了大规模语料下判定不可穷尽的问题；分级相关性 + nDCG 解决了二值判定过于粗糙的问题。

自建集的最小可用方法学集合是：pooling + 分级判定 + 官方指标。省掉任何一件，结果就不可比或不可信。这也是可直接沿用 TREC 工具链的前提——两者共用同一套 qrels 格式。

必须承认的偏差：pool bias —— 池中未判定的文档在评测时按不相关处理，新系统召回池外文档会被系统性低估。报告中应声明"本测试集用于系统间相对比较，绝对分数不作为通用基线"。

数据集设计与标注规范

Topics：30–60 条（少于 30 时差异基本不可能显著）；三要素 id / title / narrative，其中 narrative 是标注质量的生命线，须把"什么算 2 分、什么算 3 分"写到无歧义；刻意保留 20–30% 难查询。

Pooling：3–4 个系统 × Top-20，必须注入每主题 1–3 条种子正例防止池子全负。

分级含义CAD 场景示例
0不相关查雨水口却返回管段
1弱相关同为检查井，但材质或管径不符
2相关材质、管径命中，埋深缺失
3完全匹配关键参数齐全且可定位到图号

四级制与 TREC DL 一致，可直接复用 -l 2 口径。

显著性检验：小样本的必修课

30–60 个主题属小样本，只报均值等于没说。标配 paired bootstrap（B=10000）+ paired t 检验。

实测示例：A（BM25）0.3269 vs B（混合）0.3615，差值 −0.0346，95% CI [−0.1010, +0.0325]，p = 0.3068 → 不显著。数值上 B 更高，但不可宣称"混合检索显著优于 BM25"。

判读规则：95% CI 不含 0 且 p < 0.05 才可宣称显著；CI 跨 0 只能说"数值上更高"。
